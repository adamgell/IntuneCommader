01

Positioning

The thesis

cmtrace reads what happened on the endpoint. cmProjectX extends its feelers through the core into Entra & Intune and pulls that context down — so a raw log line becomes an enriched, correlated one. You stop alt-tabbing between a log viewer and the portal: the answer is on the line.

It's 50/50. Neither half is a sidekick. The diagnostics heritage and the management heritage are equal, and the brand is the seam where they meet.

Two heritages, one tool
≣ cmtrace

local logs · live tail · severity coding · dsregcmd · Sysmon · timeline

⟷
▣ IntuneCommander

tenant CRUD · assignments · compliance · drift · snapshots · restore

Form, not color, carries the 50/50: line/≣ = diagnostics, node/▣ = management. Teal leads; blue means "cloud."

08

Voice

Principles
  • Plain & precise. Say the error code and what it means.
  • Actionable. Every dead end offers the next move.
  • Calm under failure. No alarmism; diagnostics, not drama.
  • Reversible by default. Name the undo before the user asks.
Microcopy
device code
"Finish signing in from a browser — enter FQXJ-7K2D at microsoft.com/devicelogin."
error
"Can't reach the service — the sidecar may still be starting. Retry."
write confirm
"This changes 3 settings on 1,284 devices. We'll snapshot first so you can roll back."
Open items before this is final: (1) Name — "cmProjectX" is a working codename; the system is built to flex if it changes. (2) Cloud blue — currently official Intune #0078D4; swap to vivid azure #0A84FF if you want more pop. (3) Next: port these tokens into app/src (Reactor) + a light theme pass. Tell me what to push on.
